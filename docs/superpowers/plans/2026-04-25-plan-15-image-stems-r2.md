# Plan 15 — Image stems via Cloudflare R2

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Let creators upload an image when seeding an atom (ECG strip, chest X-ray, derm rash, fundoscopy, etc.). The image renders inline in `<AtomRenderer />` and `<MockQuestion />` — both already accept `imageUrl` (Plan 1's atom schema), so this plan is mostly the upload pipeline plus light wiring.

Storage: **Cloudflare R2** free tier (10 GB storage, no egress fees). The bucket is set up by the operator; the app uploads via S3-compatible presigned URLs generated by a Netlify function.

**Spec:** §4.7 (image stems, deferred from Plan 4).

**v1 simplifications:**
- One image per atom. Multi-image (carousels for clinical case series) deferred to Plan 15B.
- No server-side optimisation, resizing, or CDN-style transforms — the file goes to R2 as-uploaded.
- No NSFW / moderation filter. Creator-only upload limits the blast radius for v1.
- No EXIF stripping — clinical images shouldn't carry GPS, but this is a known gap.
- 5 MB hard cap, JPEG/PNG/WebP only.
- The bucket itself + operator credentials setup is **out of scope for the plan code** — runbook only.

**Architecture:**

1. **Cloudflare R2 bucket** — set up by operator via `wrangler r2 bucket create studyedit-atom-images` (one-shot). Public-read enabled via R2.dev custom domain or worker. Out of scope for the plan; documented in the operator runbook.
2. **Netlify function `r2-upload.ts`** — generates a presigned URL using R2's S3-compatible API (`@aws-sdk/s3-request-presigner` + `@aws-sdk/client-s3` configured against R2's endpoint). Validates the user is `isCreator` via JWT. Returns `{ uploadUrl, publicUrl, key }`.
3. **`<ImageUpload />` component** — renders a file input + drag-drop zone. On select: requests a presigned URL from the Netlify function, PUTs the file directly to R2, returns the public URL via `onUploaded(url)`.
4. **`<AtomSeedForm />` integration** — adds an "Image (optional)" field. When the user picks an image, it uploads in the background; the resolved `publicUrl` is written to `atoms.image_url` on form submit.
5. **`<AtomRenderer />` + `<MockQuestion />`** — already render `atom.image_url` when set (per Plan 1). Verify with a snapshot test; no new code expected.

**No schema changes.** `atoms.image_url` and `atoms.image_alt` already exist (Plan 1).

**New env vars (set in Netlify):**
- `R2_ACCOUNT_ID` — Cloudflare account ID
- `R2_ACCESS_KEY_ID` — R2 API token access key
- `R2_SECRET_ACCESS_KEY` — R2 API token secret
- `R2_BUCKET_NAME` — e.g. `studyedit-atom-images`
- `R2_PUBLIC_URL_BASE` — e.g. `https://images.studyedit.com` or the R2.dev URL

## Phase + task breakdown — 11 commits

### Phase A — R2 presigned-URL function (3 tasks)

**Task 1: `feat(netlify): scaffold r2-upload function with S3-compatible client`**
- Configure `S3Client` with R2's endpoint: `https://${R2_ACCOUNT_ID}.r2.cloudflarestorage.com`.
- Accept POST `{ filename, contentType }`.
- Validate auth header (`Authorization: Bearer <jwt>`); reject if missing.
- Validate `contentType` against an allow-list: `image/jpeg`, `image/png`, `image/webp`. Reject otherwise.
- Validate the user is `isCreator` (decode JWT → check `app_metadata.role`).
- Generate a key: `atoms/${user_id}/${uuid}.${ext}`.

**Task 2: `feat(netlify): generate presigned PUT URL with 5-minute expiry`**
- Use `getSignedUrl` from `@aws-sdk/s3-request-presigner` against a `PutObjectCommand`.
- 5-minute expiry (300s). Beyond that, the URL is dead and the client must request a new one.
- Cap content-length at 5 MB via signed `Content-Length` header policy.
- Return `{ uploadUrl, publicUrl: \`${R2_PUBLIC_URL_BASE}/${key}\`, key }`.

**Task 3: `test(netlify): unit test for r2-upload happy path + reject paths`**
- Mock the SDK. Test:
  - Happy path returns `{ uploadUrl, publicUrl, key }`.
  - Missing auth → 401.
  - Non-creator → 403.
  - Invalid content type → 400.
  - SDK throws → 502 with error envelope.

## Constraints

1. **No server-side image optimisation.** Images go to R2 as-uploaded. CloudFront-style transforms are deferred to Plan 15B.
2. **No moderation / NSFW filter.** Creator-only upload limits exposure for v1.
3. **No EXIF stripping.** Known gap for clinical images; documented in CHANGELOG.
4. **5 MB cap, JPEG / PNG / WebP only.** Enforced both client-side and via signed `Content-Length` policy.
5. **Presigned URL expires in 5 minutes.** Beyond that, client requests a fresh one.
6. **`image_alt` required when `image_url` set.** A11y baseline.
7. **AWS SDK is function-only.** Don't import `@aws-sdk/*` from any `src/` file — keep it isolated to `netlify/functions/r2-upload.ts` so the client bundle stays clean.
8. **Public-read URLs.** R2 bucket is public-read; the client never proxies images. No bucket-list permissions on the public token.
9. **Operator action required before merge.** The five env vars must be set in Netlify; the function will return 500 without them.
10. **Don't push, don't run real R2 calls in tests.** Mock `fetch` everywhere.
